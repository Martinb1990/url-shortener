# Operations: Kubernetes + GitOps

## Layout

| Path | What |
|---|---|
| `charts/url-shortener/` | Helm chart: app, Postgres StatefulSet, Redis, NetworkPolicies, Ingress |
| `clusters/devops01/flux-system/` | Flux itself (generated by `flux install --export`) + what it syncs |
| `clusters/devops01/apps.yaml` | Flux Kustomization for `apps/devops01`, with SOPS decryption |
| `apps/devops01/url-shortener/` | Namespace, encrypted DB secret, HelmRelease, image automation |
| `infrastructure/devops01/` | Cluster add-ons: monitoring (kube-prometheus-stack, Loki, Alloy), cert-manager, Traefik config, Headlamp |
| `infrastructure/devops01-configs/` | Resources that need the add-ons' CRDs first: Let's Encrypt ClusterIssuers |

Flux applies the layers in order: `infrastructure` → `infrastructure-configs` → `apps`.

## How a change reaches production

1. Merge a PR to `main`.
2. CI tests, scans, runs the chart on a throwaway k3d cluster, then publishes `ghcr.io/martinb1990/url-shortener:main-<UTC timestamp>-<sha>`.
3. Flux scans GHCR every 2 minutes, picks the newest `main-*` tag, and commits it to `apps/devops01/url-shortener/helmrelease.yaml` (author `fluxcdbot`).
4. Flux applies the HelmRelease. Pods roll one at a time (`maxUnavailable: 0`, 5 s `preStop` drain, so no requests fail), and a release whose pods never become ready is rolled back automatically.

## Consoles

| Tool | What | How to reach it |
|---|---|---|
| **Headlamp** | Web console: browse/edit workloads, logs, exec into pods, restart | `ssh -L 4466:localhost:4466 <user>@34.89.12.210`, then http://localhost:4466 |
| **k9s** | Terminal UI on the VM | `k9s` (`:pods`, `:deploy`, `l` logs, `d` describe, `s` shell, `ctrl-d` delete, `?` help) |
| **Grafana** | Metrics, dashboards, logs | `ssh -L 3000:localhost:3000 ...`, then http://localhost:3000 |

Headlamp login: paste a short-lived token for the `headlamp-admin` ServiceAccount (**cluster-admin**: full rights, owner's choice):

```bash
kubectl -n headlamp create token headlamp-admin --duration=12h
```

Headlamp's own ServiceAccount has no cluster rights, so reaching the page without a token grants nothing. Revoke all outstanding tokens at once by deleting and recreating the ServiceAccount (`kubectl -n headlamp delete sa headlamp-admin`; Flux recreates it).

## Day-to-day

```bash
flux get all -A                         # sync status of everything
flux get images all -A                  # what image Flux has picked
flux reconcile kustomization flux-system --with-source   # sync now
kubectl -n url-shortener get pods
kubectl -n url-shortener logs deploy/url-shortener -f
```

The app is public at **https://shortly-martin.duckdns.org** (Let's Encrypt via cert-manager, HTTP redirects to HTTPS, HSTS, per-IP rate limits). Internal UIs stay private behind the SSH tunnel: `ssh -L 3000:localhost:3000 <user>@34.89.12.210`, then Grafana at http://localhost:3000.

## Observability

| Tool | What | Where |
|---|---|---|
| Prometheus | Metrics: app (via ServiceMonitor), Kubernetes, node. 3 days / 3 GB retention | in-cluster only |
| Grafana | Dashboards + Explore for metrics and logs | http://localhost:3000 through the tunnel (`-L 3000:localhost:3000`); not on the public ingress |
| Loki + Alloy | Logs from every pod, 3 days | Grafana → Explore → Loki |
| Alertmanager | Warning/critical alerts to Discord; Watchdog to healthchecks.io (dead man's switch) | in-cluster only |
| healthchecks.io | Emails the owner if Alertmanager's per-minute Watchdog ping stops (cluster, network or VM down) | external |
| GitHub Actions `Uptime` | Every 15 min from GitHub's network: home page, `/readyz`, HTTP→HTTPS, cert ≥ 14 days | external |

Prometheus and Alertmanager have no login, so they get no ingress. Use Grafana, or a port-forward:

```bash
kubectl -n monitoring port-forward svc/kube-prometheus-stack-prometheus 9090   # then ssh -L 9090:localhost:9090 ...
```

Grafana login is `admin`; the password is SOPS-encrypted in git:

```bash
kubectl -n monitoring get secret grafana-admin -o jsonpath='{.data.admin-password}' | base64 -d; echo
```

**Dashboards:** "URL Shortener" (provisioned from `charts/url-shortener/dashboards/`) plus the stock Kubernetes and node dashboards.

**App alerts** (`charts/url-shortener/templates/monitoring.yaml`, unit-tested in `tests/monitoring/`, run with `make test-alerts`):

| Alert | Fires when | Severity |
|---|---|---|
| ShortenerDown | no app pod can be scraped for 2m | critical |
| ShortenerHighErrorRate | > 5% of requests are 5xx for 5m | warning |
| ShortenerHighLatency | p95 > 500 ms for 10m | warning |
| ShortenerDatabaseDown | Postgres not ready for 2m | critical |
| ShortenerCacheDown | Redis unavailable for 5m (app degrades, still works) | warning |

## Rollback

Revert the Flux commit that bumped the tag (`git revert <sha>` via a PR), or pin the tag by hand in `helmrelease.yaml`. To stop Flux bumping it while you investigate:

```bash
flux suspend image update url-shortener
flux resume image update url-shortener   # when done
```

## Secrets (SOPS + age)

- Encrypted with the age public key in `.sops.yaml`. Only `data`/`stringData` are encrypted, so diffs stay reviewable.
- The private key is in the cluster (`flux-system/sops-age`) and at `~/.config/sops/age/keys.txt` on the VM. **Keep an offline backup.** Without it, the secrets in git can't be decrypted.
- CI fails if a `kind: Secret` under `apps/` or `clusters/` isn't SOPS-encrypted.

```bash
sops apps/devops01/url-shortener/db-secret.sops.yaml   # edit in place (decrypts in $EDITOR)
```

## Bootstrap (one-time, already done on gcp-devops01)

```bash
# 1. Decryption key for Flux
kubectl create namespace flux-system
kubectl -n flux-system create secret generic sops-age --from-file=age.agekey=$HOME/.config/sops/age/keys.txt
# 2. Deploy key (write access, for image automation) + the secret Flux uses
flux create secret git flux-system --url=ssh://git@github.com/Martinb1990/url-shortener --namespace flux-system
#    -> add the printed public key as a deploy key with write access, and allow
#       "Deploy keys" to bypass the main ruleset
# 3. Install Flux and start syncing
kubectl apply -k clusters/devops01/flux-system
```

## Upgrading Flux

```bash
flux install --export --components=source-controller,kustomize-controller,helm-controller \
  --components-extra=image-reflector-controller,image-automation-controller \
  > clusters/devops01/flux-system/gotk-components.yaml
```

Open a PR; Flux upgrades itself after merge.
