# Operations: Kubernetes + GitOps

## Layout

| Path | What |
|---|---|
| `charts/url-shortener/` | Helm chart: app, Postgres StatefulSet, Redis, NetworkPolicies, Ingress |
| `clusters/devops01/flux-system/` | Flux itself (generated by `flux install --export`) + what it syncs |
| `clusters/devops01/apps.yaml` | Flux Kustomization for `apps/devops01`, with SOPS decryption |
| `apps/devops01/url-shortener/` | Namespace, encrypted DB secret, HelmRelease, image automation |

## How a change reaches production

1. Merge a PR to `main`.
2. CI tests, scans, runs the chart on a throwaway k3d cluster, then publishes `ghcr.io/martinb1990/url-shortener:main-<UTC timestamp>-<sha>`.
3. Flux scans GHCR every 2 minutes, picks the newest `main-*` tag, and commits it to `apps/devops01/url-shortener/helmrelease.yaml` (author `fluxcdbot`).
4. Flux applies the HelmRelease. Pods roll one at a time (`maxUnavailable: 0`), and a release whose pods never become ready is rolled back automatically.

## Day-to-day

```bash
flux get all -A                         # sync status of everything
flux get images all -A                  # what image Flux has picked
flux reconcile kustomization flux-system --with-source   # sync now
kubectl -n url-shortener get pods
kubectl -n url-shortener logs deploy/url-shortener -f
```

Reach the app from your computer: `ssh -L 8080:localhost:80 <user>@34.89.12.210`, then open http://localhost:8080.

## Rollback

Revert the Flux commit that bumped the tag (`git revert <sha>` via a PR), or pin the tag by hand in `helmrelease.yaml`. To stop Flux bumping it while you investigate:

```bash
flux suspend image update url-shortener
flux resume image update url-shortener   # when done
```

## Secrets (SOPS + age)

- Encrypted with the age public key in `.sops.yaml`. Only `data`/`stringData` are encrypted, so diffs stay reviewable.
- The private key is in the cluster (`flux-system/sops-age`) and at `~/.config/sops/age/keys.txt` on the VM. **Keep an offline backup.** Without it, the secrets in git can't be decrypted.
- CI fails if a `kind: Secret` under `apps/` or `clusters/` isn't SOPS-encrypted.

```bash
sops apps/devops01/url-shortener/db-secret.sops.yaml   # edit in place (decrypts in $EDITOR)
```

## Bootstrap (one-time, already done on gcp-devops01)

```bash
# 1. Decryption key for Flux
kubectl create namespace flux-system
kubectl -n flux-system create secret generic sops-age --from-file=age.agekey=$HOME/.config/sops/age/keys.txt
# 2. Deploy key (write access, for image automation) + the secret Flux uses
flux create secret git flux-system --url=ssh://git@github.com/Martinb1990/url-shortener --namespace flux-system
#    -> add the printed public key as a deploy key with write access, and allow
#       "Deploy keys" to bypass the main ruleset
# 3. Install Flux and start syncing
kubectl apply -k clusters/devops01/flux-system
```

## Upgrading Flux

```bash
flux install --export --components=source-controller,kustomize-controller,helm-controller \
  --components-extra=image-reflector-controller,image-automation-controller \
  > clusters/devops01/flux-system/gotk-components.yaml
```

Open a PR; Flux upgrades itself after merge.
